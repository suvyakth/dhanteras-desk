# Problems log

This feeds the required "What problems did you face during building?" answer. Add each real error or blocker, and what fixed it, as it happens.

- **2026-11-21:** Band's hacker guide says a dashboard on its own doesn't count as meaningful use of Band. A run has to end on a decision that a named human approves or blocks. We redesigned so that the owner's approval in the room is the last step, and added a Critic that can veto.
- **2026-11-21:** On the first live run, Groq returned 404 because `llama-3.3-70b-versatile` has been retired. We listed the models the key can use (`/models`) and switched to `openai/gpt-oss-120b`, the strongest one that supports tool calls.
- **2026-11-21:** Groq's free tier limits tokens per minute for each model, and Band's system prompt is long. With Planner and Critic on the same model, Critic kept getting 429 errors. We gave each agent its own model through `<NAME>_MODEL` (Critic now uses `gpt-oss-20b`) and raised retries to 6.
- **2026-11-21:** A hard limit. Band sends each agent the room's history along with every request. After a few BLOCKED/revise rounds, Planner's request reached 8,060 tokens, but Groq's free tier allows only 8,000 tokens per minute on `gpt-oss-120b`. So the request could never succeed (413). Short-term fix: a compact shop JSON and a rule that plans stay under 120 words. We couldn't switch providers: the other free tiers needed a card or weren't available to us, and every Groq model on the key is capped at 8,000 tokens per minute. So we wrapped the chat model to trim what it receives: the system prompt plus only the newest messages within a character budget (`HISTORY_CHARS`), never starting on an orphaned tool result. The full record stays in the Band room for people to read.
- **2026-11-21:** `gpt-oss-20b` sometimes leaked its internal format tokens into tool names (`band_send_message<|channel|>commentary`), so Groq rejected the call. We tested `qwen/qwen3.8-27b` three times on a sample tool call, it worked every time, and Critic moved to it. But in the live room, Qwen never ended its turn: it called `band_send_message` 16 times in one turn, until it hit LangGraph's 50-step limit, and flooded the room. Fixes: Critic went back to `gpt-oss-120b` (the model Planner uses without trouble), its prompt now says "call band_send_message exactly once, then stop", and every agent's turn is capped at 12 graph steps so a misbehaving model can't spam the room.
- **2026-11-21:** We hit Groq's daily cap of 200,000 tokens per model on `gpt-oss-120b`. Each Band turn costs about 5,000 tokens (Band's system prompt, its tool schemas, and the trimmed history), and the agents were also re-processing a backlog of 16 spam messages. Lesson: a free LLM tier can't run a token-heavy agent loop. Decision: move the heavy reasoning to Lyzr, which doesn't bill tokens, and keep the Band agents thin.
- **2026-11-21:** Lyzr's quickstart docs show `POST /v3/agent`, but that returns 405. We found the live endpoints by sending empty requests: an empty POST to `/v3/agents/` returned 422 and listed the required fields (`provider_id`, `model`, `top_p`, `temperature`). Chat uses `/v3/inference/chat/`. Separately, the key was first saved as `LYZR_API_KEY=LYZR_API_KEY=…`, which Lyzr rejected as "Invalid API key".
- **2026-11-21:** In the smoke test, the Lyzr Critic sometimes left out the `TO:` routing line. Now, when there's no `TO:` line, the agent replies to whoever @mentioned it, and only an explicit `TO: none` keeps it silent.
- **2026-11-21:** The dev machine is a managed school laptop. Nothing can be exposed on a public port and no native tools can be installed. So anything that has to be reachable from outside goes to the cloud (Lyzr Studio, Band cloud, Agent37).
- **2026-11-21:** Band rejected messages with `cannot_mention_self` when an agent's LLM put its own handle (for example `ozardravindra/critic`) in its reply. Code now strips the agent's own name in any spelling. If Band still refuses, the agent replies to whoever asked.
- **2026-11-22:** gpt-4o-mini on Lyzr has no web access, so Scout made up plausible-looking article URLs (`…/article6612345.ece`), some about gold and silver, which the shop doesn't sell. Scout now pulls real headlines from Google News RSS (no key needed) for the shop's own items, and its Lyzr agent may cite only those, by number. Code turns each number into the real link and drops any line that cites nothing fetched, along with any URL the model wrote itself. Old news (a 2015 article came up) is filtered to the last 120 days.
- **2026-11-22:** Scout and Critic sometimes addressed the owner instead of a teammate, and the run stalled. A prompt alone didn't fix this reliably, so the routes are now set in code: Scout reports to Planner and Critic, and Critic reports only to Planner.
- **2026-11-22:** With Scout copying both Planner and Critic, both answered at once. Critic judged raw findings as if they were a plan and blocked them, and Planner kept re-asking Scout. The room filled with BLOCKED messages. Now Critic quietly files Scout's findings and judges only plans. Planner asks Scout only once per run, and code turns any second ask into a send to Critic.
- **2026-11-22:** The LLMs couldn't do the restock arithmetic reliably: 0 diyas one turn and 45 the next, wrong totals, and an over-budget plan sent to the owner. Arithmetic moved into code. Planner gets a sales-based baseline (weekly sales × 3 festive weeks − stock), every plan is stamped with a code-computed total, and Critic cannot approve a plan that fails the code check. Planner and Critic moved from gpt-4o-mini to gpt-4.1.
- **2026-11-22:** Once Critic had approved, Planner rewrote the numbers in its message to the owner (70 → 74 kaju katli). The owner would have approved a plan Critic never saw. Now code sends the owner, word for word, the plan Critic approved.
- **2026-11-22:** After a restart, Band redelivered 15 leftover messages from an earlier run. Each one started a new Planner ↔ Critic round, and the room flooded. We cleared the backlog through Band's message API (each message must be marked `processing` before `processed`). Agents now ignore any message sent before they started.
- **2026-11-22:** Band mention names are case-sensitive. Planner's LLM wrote `critic`, and Band raised "Unknown participant 'critic'". Every mention is now mapped to the exact handle in code.
- **2026-11-22:** Two messages from the owner never reached the agents. `@Planner` had been typed as plain text, not picked from the dropdown as a chip, so Band attached no mention and delivered nothing. We found it by reading each agent's view of the room through Band's context API.
- **2026-11-22:** In a live run, Planner cut dry-fruit gift boxes to 0 and left ₹22,680 of the budget unspent, and Critic approved it. The code check now blocks any cut of more than half the baseline, and any budget cut that leaves more than 10% of the budget unused.
- **2026-11-22:** Planner kept sending Critic drafts that the code check had already failed (over budget, cuts too deep), so Critic's two vetoes went on arithmetic and the run escalated without an approval. Now a failing draft goes back to Planner once, privately, with the exact problems. A thought event shows this in the room. Critic's veto is left for judging evidence, and in testing it caught Planner citing an E3 that didn't exist.
